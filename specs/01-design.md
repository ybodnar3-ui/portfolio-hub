# Portfolio Hub — дизайн

**Дата:** 2026-07-31
**Статус:** затверджено до планування

## Мета

Один додаток, у якому зібрано всі vibe-coding проєкти Юри. Закриває три різні потреби над одним набором даних:

1. **Вітрина** — посилання, яке можна кинути клієнту, тренеру чи в універ.
2. **Бібліотека фіч** — знайти раніше зроблену фічу, побачити її живою, скопіювати код.
3. **Дошка стану** — зрозуміти, який проєкт завершений, який треба фіксити, який зламався, і скільки годин у кожен реально вкладено.

Ключове рішення: це **не три сайти**, а три режими над спільним `data/`. Розсинхрону між ними бути не може за побудовою.

## Стек і розміщення

- Next.js 16 (App Router), React 19, TypeScript, Tailwind 4 — той самий стек, що в `shader-app` і `spotlight-demo`.
- Живе в `~/Claude/portfolio` як окремий git-репозиторій.
- Деплой на Vercel.
- Жодних імпортів з інших проєктів. Фічі **копіюються** всередину хаба, тому правки в `artpro` чи `revela-store` не можуть його зламати.
- Бази даних немає. Все — статичні файли в git.

## Структура репозиторію

```
portfolio/
  app/
    page.tsx                 # вітрина
    work/[slug]/page.tsx     # кейс проєкту
    lab/page.tsx             # каталог фіч
    lab/[slug]/page.tsx      # фіча: демо + код + нотатки
    board/page.tsx           # CRM-дошка
    login/page.tsx           # форма пароля
    api/login/route.ts       # ставить cookie
    api/board/route.ts       # PATCH статусу (тільки dev)
    api/time/route.ts        # старт/стоп/правка сесій (тільки dev)
  components/               # site-header, live-preview, board-card, timer-* тощо
  lib/
    types.ts  data.ts  status.ts  time.ts  write.ts
    merge.mjs                # злиття даних сканера (JS, бо його ділить scan.mjs)
  data/
    projects.json
    features.json
    time.json                # сесії таймера, окремо бо часто змінюється
  public/
    features/<slug>/index.html   # самодостатнє демо фічі
    features/<slug>/notes.md
    shots/<slug>.webp            # скріншоти проєктів, комітяться в git
  scripts/
    scan.mjs                 # чернетки карток з файлової системи
    shots.mjs                # скріншоти: live URL, або локальний HTML через file://
    health.mjs               # пінг live URL → прапорець broken
  tests/                     # vitest на чисту логіку: time, status, merge
  middleware.ts              # пароль на /lab і /board
```

`public/shots/` **не** в `.gitignore`: Vercel збирає з git, і без закомічених знімків вітрина на проді була б порожньою — `shots.mjs` вимагає Playwright і живих сайтів, на Vercel він не запуститься.

## Модель даних

### `data/projects.json`

```jsonc
{
  "slug": "revela-store",
  "title": "REVELA",
  "tagline": "Магазин миттєвих і плівкових камер",
  "story": "Кастомний магазин замість Shopify, генерується з build/data.js…",
  "kind": "web",             // web (є що показати в iframe) | deck (презентація) | doc (звіт)
  "stack": ["vanilla JS", "Vercel"],
  "liveUrl": "https://revela-store.vercel.app",
  "localPath": "~/Claude/revela-store",
  "tags": ["ecommerce", "dark", "TETR"],
  "status": "done",              // idea | in-progress | finishing | needs-fix | done | archived
  "featureSlugs": ["film-develop"],
  "nextStep": "",                // одним рядком, показується на дошці
  "blocker": "",                 // якщо не порожній — жовтий прапорець
  "lastTouched": "2026-07-22",   // автогенерується
  "health": "ok"                 // ok | broken | unknown — автогенерується.
                                 // unknown = немає liveUrl (презентації, звіти, локальні експерименти)
}
```

### `data/features.json`

```jsonc
{
  "slug": "video-lock",
  "title": "Замок на відео",
  "summary": "Структура контенту відкрита всім, самі відео замкнені до оплати",
  "tags": ["access", "video", "paywall"],
  "fromProject": "artpro",
  "deps": []                     // порожньо = ванільний JS, нічого не треба ставити
}
```

### `data/time.json`

Тримається окремо від `projects.json`, бо змінюється щодня і засмічував би діфи карток.

```jsonc
{
  "running": {                        // максимум один запущений таймер
    "projectSlug": "aquastar",
    "startedAt": "2026-07-31T14:02:11.000Z"
  },
  "entries": [
    {
      "id": "e_0041",
      "projectSlug": "aquastar",
      "startedAt": "2026-07-30T09:15:00.000Z",
      "endedAt": "2026-07-30T11:40:00.000Z",
      "minutes": 145,
      "note": "форма + телеграм-інтеграція",
      "source": "timer"               // timer | manual
    }
  ]
}
```

`minutes` зберігається явно, а не рахується з дат — щоб ручні правки й округлення не залежали від того, як хтось потім парсить ISO.

Поля `status`, `nextStep`, `blocker`, описи й теги ставляться людиною. `lastTouched` перезаписує `scan.mjs`, `health` — `health.mjs`. Обидва **ніколи не затирають** рукописні поля: тільки додають нові картки й оновлюють своє автополе.

## Режим 1 — Вітрина (публічна)

- `/` — герой + сітка робіт (14 із 17 проєктів; архівні приховані). Картка проєкту показує статичний скрін як постер; живий `<iframe>` самого сайту підвантажується тільки на hover. Це не дає сторінці тягнути 14 айфреймів одночасно.
- `/work/[slug]` — кейс: легенда, стек, дата, кнопка на live-сайт, секція «Фічі звідси» з переходом у Lab.
- Архівні проєкти на вітрині не показуються.
- Проєкти типу `deck` і `doc` (презентації, звіти) показують типографічну заглушку замість превʼю — PDF в iframe вантажиться довго й виглядає погано. Те саме для будь-якого проєкту без скріншота, щоб не було битих картинок.

Візуальний напрям: темний, кінематографічний, serif-заголовки, кастом-курсор, стримана анімація появи секцій. Хаб сам має бути демонстрацією смаку — це головний аргумент вітрини.

## Режим 2 — Lab (приватна)

- `/lab` — щільна сітка фіч, миттєвий пошук по назві й тегах, фільтр по типу.
- `/lab/[slug]` — три зони: живе демо в `<iframe sandbox="allow-scripts">`, код із кнопкою копіювання, нотатки з `notes.md` (чому так зроблено, що міняти під новий проєкт).

Кожна фіча — самодостатній `public/features/<slug>/index.html`, який працює, якщо відкрити його напряму в браузері. Сторінка фічі читає **цей самий файл** двічі: рендерить в iframe і показує як текст. Одне джерело — код у превʼю і код у панелі не можуть розійтися.

Витягування фічі з проєкту робиться на вимогу («витягни знімок, що проявляється, з revela-store»), не масово наперед.

## Режим 3 — Board (CRM)

- `/board` — канбан на шість колонок: **Ідея · В роботі · Фініш · Треба фікс · Готово · Архів**.
- Картка: назва, останній дотик, наступний крок, прапорці.
- Два прапорці поверх колонок, бо вони ортогональні етапу:
  - 🔴 **broken** — `health.mjs` не отримав 200 з live URL. Ламаються і готові проєкти теж, тому це не колонка.
  - 🟡 **stale** — останній дотик понад 60 днів тому, а статус не `done` і не `archived`.
- Клік на картку веде в `/work/[slug]`. Кнопка таймера й ручка для перетягування клік далі не пропускають.

### Таймер

Мета — знати, скільки годин реально пішло на проєкт, щоб адекватно рахувати ціну наступних.

- На кожній картці кнопка **старт/стоп** і накопичений час (`14 год 20 хв`).
- Одночасно може йти **тільки один** таймер. Старт нового автоматично зупиняє попередній і записує його сесію — так не буває двох паралельних лічильників, які ти забув вимкнути.
- Запущений таймер видно глобально в шапці, на всіх трьох режимах. Забути про нього важко.
- `/work/[slug]` показує розбивку: список сесій з датами, нотатками й сумою.

**Запобіжники від забутого таймера:**

- Сесія довша за **6 годин** при зупинці не зберігається мовчки — виходить діалог із підставленим фактичним часом, який можна виправити. Поки діалог не закрито, сесія не записана: закрити його, не підтвердивши, означає скасувати запис.
- Якщо таймер лишився запущеним з попереднього дня, при відкритті хаба спрацьовує той самий діалог: «Таймер по `aquastar` іде з учора, 14:02. Скільки з цього справді робота?»
- Будь-яку сесію можна відредагувати або видалити; можна додати сесію заднім числом (`source: "manual"`).

**Що це дає для ціноутворення.** На `/board` вгорі — зведення: години по проєктах, відсортовані за спаданням, з поділом на типи (лендінг, магазин, презентація). Видно реальну вилку: «магазин — 18–26 год», «лендінг — 9–14 год». Це і є база для розрахунку ціни, а не відчуття.

**Редагування.** Drag-and-drop і таймер працюють тільки на localhost: перетягування шле `PATCH /api/board` (переписує `status` у `projects.json`), старт/стоп шле `POST /api/time` (пише в `time.json`). Ти комітиш — історія стану й витраченого часу живе в git. На Vercel `NODE_ENV === 'production'` обидва роути повертають 403: дошка read-only, таймер показує накопичене, але не запускається.

## Скрипти

| Скрипт | Що робить | Коли ганяти |
|---|---|---|
| `scan.mjs` | Проходить `~/Claude`, знаходить проєкти, читає `package.json`, `.vercel/project.json`, mtime та `.planning/HANDOFF.json`. Додає нові картки-чернетки, оновлює `lastTouched`. | Коли зʼявився новий проєкт |
| `shots.mjs` | Playwright знімає `public/shots/<slug>.webp`. Джерело — `liveUrl`, а якщо його немає, локальний HTML через `file://`. Так у вітрини є постери й для незадеплоєних робіт. | Після `scan` |
| `health.mjs` | Пінгує кожен `liveUrl`, ставить `health: ok \| broken` | Раз на тиждень або вручну |

`.planning/HANDOFF.json` у наявних проєктах — порожні автозаписи без реальної фази. Корисний з них тільки `timestamp`. Етап проєкту автоматично не виводиться, ставиться руками.

## Доступ

`middleware.ts` закриває `/lab` і `/board` паролем із `LAB_PASSWORD` (cookie після сторінки входу). Це захист від випадкового перехожого, не справжня безпека — чутливі речі (ціни клієнтів, внутрішні легенди) у нотатки не пишемо.

## Обсяг першої ітерації

**Входить:** три режими, таймер із запобіжниками та зведенням годин, `scan.mjs`, `shots.mjs`, `health.mjs`, 17 проєктів у `projects.json`, 5 фіч у Lab (замок на відео, знімок що проявляється, інтерактивне SVG-креслення за розміром, поява секцій при скролі, магнітне притягання).

**Свідомо не входить:** база даних, CMS, real-time, аналітика, багатокористувацький доступ, drag-and-drop і таймер у продакшені, автоматичне визначення етапу, ставки й рахунки в грошах (таймер дає години — ціну рахуєш сам), автотрекінг часу через git-коміти чи активність редактора.
