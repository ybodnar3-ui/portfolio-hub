# Хаб — внутрішній

> Гілка `internal`. Публічної вітрини тут немає: сторінка кейсів житиме на сайті агенції.
> Повна версія з вітриною лишилась у гілці `main`.

Інструмент, щоб самому вести свої проєкти: що в роботі, що зламалось, скільки годин пішло.

Next.js 16 · React 19 · TypeScript · Tailwind 4 · Vitest. Бази даних немає: усі дані —
статичні JSON у git.

---

## Що всередині

| Сторінка | Що робить |
|---|---|
| **Дошка** `/` | Канбан на шість колонок, прапорці «зламано» і «застояно», таймер обліку часу, зведення годин і створення нових проєктів. |
| **Проєкт** `/work/[slug]` | Опис, стек, розбивка витраченого часу, нотатки. Усе редагується просто тут. |
| **Lab** `/lab` | Бібліотека фіч: живе демо, код із кнопкою копіювання, нотатки як вбудувати. |

Весь хаб під паролем — публічної частини немає.

---

## Запуск локально

```bash
npm install
```

Створити `.env.local` (у git не потрапляє):

```
LAB_PASSWORD=свій-пароль
```

```bash
npm run dev
```

Далі `http://localhost:3007` (порт закріплений у `.claude/launch.json`, бо 3000 зайнятий).
Пароль питається один раз, cookie живе 30 днів.

### Щоб хаб був завжди

```bash
npm run autostart:install
```

Ставить агент `launchd`, який піднімає хаб при вході в систему і повертає його,
якщо процес упав. Стан — `npm run autostart:status`, прибрати — `npm run autostart:uninstall`.
Логи в `logs/hub.log`.

Агент запускає саме `next dev`, а не продакшн-збірку: усі роути запису перевіряють
`NODE_ENV !== 'production'`, а `next start` виставляє production примусово — у постійно
запущеному хабі не працювали б ні таймер, ні редагування.

### Таймер із терміналу

Хаб живе в браузері, а працюєш ти в редакторі. Щоб не перемикатись:

```bash
t                       # що зараз іде
t aqua                  # почати (нечіткий пошук за назвою й слагом)
t stop                  # зупинити
t stop 90               # зупинити й записати 90 хвилин замість виміряних
t add aqua 2.5 "форма"  # записати 2,5 години заднім числом
t ls                    # останні сесії
```

Команда `t` — функція в `~/.zshrc`, яка викликає `scripts/t.mjs`. Вона ходить через API
запущеного хаба, а не пише у файли напряму: інакше відкрита вкладка показувала б
застарілий стан. Якщо хаб не піднятий — скаже про це й підкаже команду.

Інші команди:

```bash
npm test          # vitest, чиста логіка: time, status, merge
npm run build     # продакшн-збірка
```

## Скрипти

| Команда | Що робить | Коли ганяти |
|---|---|---|
| `npm run scan` | Обходить `~` і `~/Claude`, знаходить проєкти за `.git`, `package.json`, `requirements.txt` чи `index.html`. Читає стек, `.vercel/project.json` і дату останнього коміту. Додає нові картки-чернетки, оновлює `lastTouched`. | Коли зʼявився новий проєкт |
| `npm run shots` | Playwright знімає `public/shots/<slug>.webp`. Джерело — `liveUrl`, а якщо його немає, локальний HTML через `file://`. | Після `scan` |
| `npm run health` | Пінгує кожен `liveUrl`, ставить `health: ok \| broken`. | Раз на тиждень або вручну |

**Скрипти не затирають рукописне.** `scan.mjs` чіпає тільки `lastTouched` і додає нові
картки; `health.mjs` — тільки `health`. Описи, теги, статуси й наступні кроки, написані
руками, недоторканні. Merge також нічого не видаляє: проєкт, який зник з диска, лишається
в портфоліо.

## Чому запис працює тільки локально

Редагування, таймер і створення проєктів пишуть у ті самі JSON через API-роути.
Кожен роут перевіряє `NODE_ENV` і на продакшні повертає **403**:

- на localhost — усе редагується, ти комітиш, історія живе в git;
- у продакшн-збірці — тільки читання.

Захист двошаровий: без cookie API віддає **401**, з cookie на проді — **403**.
Перше — «зайди», друге — «тут не пишуть».

Це не обмеження, а спосіб обійтись без бази: джерело правди — git, а не сервер.

## Два поля, які описують проєкт

| Поле | Значення | Навіщо |
|---|---|---|
| `kind` | `web` · `app` · `tool` · `deck` · `doc` | Як малювати картку. `web` і `app` показуються в iframe на hover; `tool` (скрейпер, бот) інтерфейсу не має, тому картка малює стек; `deck` і `doc` — типографічну заглушку. |
| `origin` | `client` · `product` · `study` · `practice` | Чи це справжня робота. На цій гілці ні на що не впливає — фільтр за ним був у вітрини. Лишений, бо `main` ним користується. |

`origin` навмисно окремо від `status`: «навчальне завдання» — це не етап роботи, і плутати
одне з одним означало б скласти TETR-завдання в ту саму купу, що й покинуті експерименти.

Ще є `repo` — назва папки на диску. Саме за нею звіряється `scan.mjs`, тому публічний слаг
можна знеособити (`relations-crm` замість `emmanuil-project`), і сканер усе одно впізнає
проєкт, а не додасть дубль.

## Як додати новий проєкт

**З інтерфейсу.** Кнопка **+ Проєкт** на дошці: назва, тип, звідки, колонка. Слаг
генерується з назви — кирилиця транслітерується, збіги отримують номер. Далі відкриється
сторінка проєкту, де кнопкою **Редагувати** дописується решта.

**Зі сканера** — коли проєкт уже є на диску:

```bash
npm run scan
```

Зʼявиться картка-чернетка зі статусом `idea` і `origin: practice`, поки не підвищиш її руками.

## Що можна правити з інтерфейсу

| Де | Що |
|---|---|
| дошка | статус — перетягуванням картки між колонками |
| дошка | таймер: старт, стоп, виправлення довгої сесії |
| дошка | створення нового проєкту |
| сторінка проєкту | назва, підзаголовок, опис, тип, звідки, колонка, посилання, стек, теги, наступний крок, блокер |
| сторінка проєкту | нотатки — стрічка коментарів з датою, додати й видалити |

Автополя (`lastTouched`, `health`) через форму не змінюються: їх веде `scan.mjs` і `health.mjs`.
`slug` теж незмінний — він і ключ, і адреса сторінки.

Усе це працює **тільки на localhost**: у продакшн-збірці роути запису віддають 403.

Після додавання проєкту, який уже задеплоєний:

```bash
npm run shots     # зняти постер
npm run health    # перевірити, що URL відповідає
```

## Як витягти нову фічу

1. Знайти код у проєкті-джерелі.
2. Зібрати `public/features/<slug>/index.html` — увесь CSS і JS всередині файлу,
   без збірки, без імпортів, без CDN.
3. **Критерій готовності жорсткий: файл відкривається подвійним кліком у браузері й працює.**
   Не працює автономно — не працюватиме і в iframe.
4. Написати `notes.md`: що робить, як вбудувати, на що звернути увагу.
5. Додати запис у `data/features.json` і слаг у `featureSlugs` проєкту-джерела.

Сторінка фічі читає той самий `index.html` двічі — віддає в iframe і показує як текст.
Одне джерело: код у превʼю і код у панелі не можуть розійтися. Дублювати код фічі
в JSON чи JSX не можна.

## Структура

```
app/          сторінки й API-роути
components/   UI
lib/          types, data, time, status, merge, write — уся логіка тут
data/         projects.json, features.json, time.json
public/
  features/   самодостатні демо фіч
  shots/      постери проєктів (комітяться)
scripts/      scan, shots, health
tests/        vitest на чисту логіку
specs/        технічні завдання
docs/         журнал роботи й рішення
```
