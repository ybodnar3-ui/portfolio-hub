# Що робить

Блоки підʼїжджають знизу й проявляються, коли входять у видиму частину екрана. Один раз:
після появи спостерігач знімає елемент з нагляду, тому блок не мигає при гортанні вгору-вниз.
Дітям контейнера можна роздати наростаючу затримку — вийде каскад.

Переписано з `Reveal.tsx` (framer-motion) на голий `IntersectionObserver`. Це десятки рядків,
тягнути заради них React і motion немає сенсу.

# Як вбудувати в новий проєкт

- Скопіюй `index.html` або лише блок `.reveal` з CSS плюс IIFE зі скрипта.
- Розмітка: повісь `data-reveal` на все, що має зʼявлятись. Більше нічого не треба.
- Каскад: `data-cascade` на контейнер, і його діти отримають `--i` та зсунуту затримку.
- `rootMargin: '0px 0px -80px 0px'` змушує спрацьовувати трохи раніше нижнього краю —
  блок встигає доїхати до того, як користувач на нього дивиться. Без цього поява
  завжди «запізнюється».

# На що звернути увагу

- **Початковий стан — видимий.** Клас `.reveal`, який ховає елемент, ставить сам скрипт
  і тільки після того, як переконався, що зможе його показати. Якщо JS не виконався,
  впав або заблокований — контент просто на місці. Класична помилка тут — прописати
  `opacity: 0` у CSS: тоді будь-яка поломка скрипта робить сторінку порожньою назавжди.
- За `prefers-reduced-motion: reduce` анімації немає **взагалі**: скрипт виходить раніше,
  ніж щось приховає. Це не «швидша поява», а її відсутність.
- Те саме, якщо `IntersectionObserver` недоступний — виходимо, нічого не ховаючи.
- `unobserve` після появи обовʼязковий: без нього спостерігач тримає посилання на всі
  елементи сторінки до кінця сесії.
- Миттєвий стрибок (`scrollTo` в кінець, перехід по якорю) не покаже блоки, повз які
  сторінка «пролетіла» — вони не потрапили в жоден кадр перетину. Для якорів це нормально,
  але якщо важливо, додай прохід по всіх елементах вище поточної позиції.
